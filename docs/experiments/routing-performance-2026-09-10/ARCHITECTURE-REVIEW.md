# Architecture review

The implemented candidate improves reusable preparation and reduces duplicate allocations. It is a concrete private review candidate, not a claim that geographic topology paging is complete or that all architectural options are exhausted. The remaining hosted WV instability is real. A lower retained heap is not a substitute for a successful repeated request below the runtime's memory ceiling.

## Recommended direction

Keep the reversible preparation improvements as an incremental candidate. Do not interpret the isolated WV success as permission for national promotion: its repeated hosted memory failure remains unresolved.

For a larger architectural change, prioritize immutable **per-region prepared routing data plus a complete exact seam directory**, then evaluate geographic topology access and stronger guidance over it. The local joined sidecar demonstrates that the current engine can consume derived topology without retaining original source graph buffers. It does not yet establish a scalable set of artifacts: preparing a separate full join for every possible region combination grows poorly as routes and edits change the region set.

A federated reference must reproduce the current join's node identities, overlap equivalence, aliases, directed access and restriction sequences. Unloaded regions and pages must remain discoverable. Fuel visits and continuation state must survive boundaries/eviction. The geometric-directory experiment should follow that correctness foundation, rather than treating a smaller random page cache as the architecture.

The WV sidecar is about593MB in addition to about418MB of original geometry read at startup; it saves join work and retained source graphs but does not guarantee fewer transported bytes. Its23.8s build is charged separately. The NSNB sidecar takes1.16s to build, so its first-use generation cost is not free. These artifacts remain local; no map pack was rebuilt, replaced or published.

No always-running service, paid infrastructure or larger runtime has been provisioned. The private previews inherit the existing project's actual4GB runtime; their performance cannot establish the accepted2GB deployment's capacity. A decision to publish derived artifacts or adopt a different serving architecture must include private hosted measurements, artifact invalidation/versioning, storage/read costs, concurrency limits, and native parity planning. This review does not claim a production-ready architecture recommendation beyond the scoped incremental candidate.
